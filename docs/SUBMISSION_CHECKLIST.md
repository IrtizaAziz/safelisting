## Engineering truthfulness
- [ ] No demo fixture is described as verified township geometry or measured real-world impact.
- [ ] No fabricated pilot KPIs or model accuracy metrics.
- [ ] Key flows are interactive and can be reproduced offline.
- [ ] Demo screen states distinguish **simulated** from **real** data.
- [ ] No secrets, resident PII, borrowed logos or unlicensed imagery.
- [ ] Mobile and desktop demo checked, including keyboard navigation.
- [ ] `npm run check` passes in the final commit; live backup recording/screenshots available.

## 90-second demo outline (working draft, not formal organizer instructions)
1. 0–20s: Show one real user problem with sourced evidence.
2. 20–60s: Show one functional change in the mechanism (e.g., new barrier changes route).
3. 60–80s: Show one township operator response or scalable outcome.
4. 80–90s: State what is proven, what is simulated, and the pilot validation plan.
