# SafeListing — design system reference

Use [MASTER_DESIGN.md](MASTER_DESIGN.md), version 1.0, as the single visual source of truth. It is the finalised specification for SafeListing — AI-Powered Rental Listing Trust.

The selected direction uses Plus Jakarta Sans and four SDP-inspired accents: red `#D71920`, ember orange `#F15A22`, warm orange `#F58220` and gold `#FCAF17`. These are class-B measured official-web values, not corporate brand specifications. Use the master's complete semantic tokens, themes, component states and accessibility rules; this summary does not override them.

Record CURRENT, field MATCH, CONTRADICTION, NOT VERIFIED and critical lifecycle states have distinct meanings and treatments. Describe real implemented checks truthfully, label simulated operations as simulated, and disclose fictional test identities/property/authority separately. Fictional authority data is never independently legally verified by signing it. Follow the master's section 16 for context-specific copy.

The immutable functional requirements in `../01_PRD.md`, `../02_USER_FLOWS.md` and `../04_SCREENS_INTERACTIONS.md` retain functional authority. The root [DESIGN.md](../DESIGN.md) preserves shared engineering boundaries. Screen creation and implementation require a separately authorised task.
